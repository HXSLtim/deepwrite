## 1. 目标与非目标

**目标**：把 NovelOps v2.10 的 G0-G8 门禁写作流程接进 DeepWrite 创作域，成为可调用的"连载模式"——新书立项与逐章推进都在 DeepWrite 原生结构上运转。

**非目标**：Python 量化工具与 AIText 模型（搁置，G5 走 LLM 自检）；22 动态轨导入（原生结构替代）；产品化门禁 UI；对外分发的版权合规（自用，分发前另行原创化/授权）。

## 2. 核心原则

1. **状态用原生**：卷/章卡/人物/世界观/伏笔/时间线/连续性 = 唯一状态源；流程中所有 NovelOps 轨道引用重写为原生结构名。
2. **落盘走 proposal**：流程的一切写入（含 G0 立项产出）经差异审阅落盘，与审批档位体系并存。
3. **方法论进提示词与技能库**：门禁逻辑进连载智能体系统提示词；知识资产（文风六卡/反AI/技法卡/题材库）进技能库按需加载。

## 3. 形态：创作域"连载"子智能体 + 四组技能库条目

### 3.1 技能库导入（用户本地库，四组）
1. **文风层**：文风六卡 + 反 AI 清单（同组，互为单一真相源）
2. **技法卡层**：路由 + 索引 + 15 分册（438 卡；凭证制：按章型检索、只取结论）
3. **流程层**：ORCHESTRATOR 四文件 + prompts/×5 + static/prompts/×10，**拆解重写为 DeepWrite 版**（引用改原生结构；番茄系默认值参数化为作品设置；USAGE 滞后不导入）
4. **题材库**：题材指南/钩子系统/角色模板/力量体系/书名模式

导入落点：用户本地技能库（folder-catalog skill domain），保留中文文件名（本地无碍且避免断链）。

### 3.2 连载多智能体（创作域，复用现有团队/子智能体机制）
- **形态**：ORCHESTRATOR（重写后）= 主编父智能体的门禁提示词，运行于创作域 agentTeamMode=team；NovelOps 角色提示词**直接移植为子智能体档案**——`prompts/`×5（writer/editor/humanizer/仿写/续写）与 `static/prompts/`×10（阶段0 角色：选题/市场/人物/大纲/节奏/QC…）。角色定义本体近原样保留；仅重写其中 `dynamic/`/`static/`/`knowledge/` 路径引用为 DeepWrite 原生结构名/技能库条目，番茄系默认值参数化。
- 工具面 = 现有创作域工具（结构操作/素材/技能加载/搜索）；子智能体注册走既有 subagent 机制，不新增契约域。
- **G 映射**：
  - G0 新书：访谈式立项 → 创意卡/大纲/人物以 proposal 写入长篇结构
  - G1 跳过：原生上下文注入替代台账加载
  - G2 样本：素材库样本条目 + web search（空库默认特征兜底）
  - G3 写作：章卡规划（Scene-Sequel、禁"干净成功"）→ 技法卡凭证 → 正文生成（R1-R5 + 每句四关 + Humanizer 单遍）
  - G4/G6 质检：智能体自检清单（editor 七步 + 文风卡6 体检）+ 原生一致性/伏笔/时间线校验
  - G5 指标：LLM 自检降级（gate-log 思想记入会话）；失败回环最多重写 1 次
  - G7 落盘：原生 proposal 差异审阅
  - G8 终审：前 3 章流程级要求"等待用户确认再继续"（软约束，档位强制力后续版本再做）
- 入口：创作空间会话中启用连载团队（主编 + 角色子智能体）；触发语（"写下一章/继续写作/启动新书"）写入门禁提示词。

## 4. 关键实现点

1. **路径重写**：流程层文档中 `dynamic/`、`static/`、`knowledge/` 引用系统性改写（主要人工成本）。
2. **子智能体注册**：contracts 子智能体档案 schema + adapter 定义 + renderer 默认子智能体设置接线，按既有 subagent 机制走，不新增契约域。
3. **技能库种子**：以导入命令/清单方式生成条目（Core 唯一写入者约束不动），中文文件名保留。
4. **web search 依赖**：G2/市场调研依赖创作域 webSearchEnabled；关闭时显式降级提示。
