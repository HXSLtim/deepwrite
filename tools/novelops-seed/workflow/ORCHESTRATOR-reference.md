## 二、质量标准

### 2.1 核心指标阈值

**硬门禁指标（纯统计，不依赖词库）**：

| 指标                   | 门限值   | 人写区间  | AI区间  | 说明          |
| -------------------- | ----- | ----- | ----- | ----------- |
| σ²（句长方差）             | ≥8    | >10   | <5    | 衡量句式多样性     |
| TTR（用词多样性）           | ≥0.40 | >0.48 | <0.30 | 衡量词汇丰富度     |
| Pσ²（段落长度方差）          | ≥20   | >28   | <12   | 衡量段落节奏      |
| BurstCV（句长变异系数）      | ≥0.40 | >0.50 | <0.30 | GPTZero核心指标 |
| ParaCV（段长变异系数）       | ≥0.30 | >0.40 | <0.20 | 段落节奏变化度     |
| 3gramRep（3-gram重复率）  | ≤0.08 | <0.06 | >0.10 | 短语复用程度      |
| 3gramUniq（3-gram唯一率） | ≥0.85 | >0.90 | <0.70 | 短语多样性       |

**参考指标（仅预警，不做硬门禁）**：

| 指标           | 门限值    | 说明           |
| ------------ | ------ | ------------ |
| EGR（情感颗粒度比）  | ≤2.0   | 依赖词库，易误判特定题材 |
| Cσ²（连接词密度方差） | ≥0.15  | 依赖词库         |
| Iσ²（信息密度方差）  | ≥1.8   | 卷级参考         |
| 对话占比         | 5%-65% | 异常值预警        |
| 标点CV         | ≥0.30  | 标点节奏参考       |

**其他指标**：

| 指标          | 门限值   | 人写区间  | AI区间 | 说明      |
| ----------- | ----- | ----- | ---- | ------- |
| FP（语言指纹匹配）  | ≥2次/章 | >3    | =0   | 个人习惯用语  |
| SC（文风稳定性系数） | ≥0.75 | >0.85 | <0.6 | 跨章指标稳定性 |

## 三、故障恢复协议

### 3.1 会话断开恢复

**场景**：写作过程中会话意外断开（如超时、网络中断、进程崩溃）。

**恢复流程**：

1. 读取 `门禁执行记录（章卡元数据）`，确认断开时最后通过的门禁：

   * G3写作中断 → 读取 `chapters/chXXX_draft.md` 草稿，从断点继续

   * G4/G5/G6质检中断 → 重新执行当前门禁

   * G7落盘中断 → 检查已落盘的文件，补全未完成的WRITE-CHECK

   * 上一章G7已通过 → 正常开始下一章

2. 读取 `进度（章卡/卷元数据）` 确认当前章号

3. 读取22个动态轨恢复全部状态

4. 从断开点继续执行，不重复已完成的步骤

**草稿文件**：

* G3写作的草稿即 `chapters/chXXX_draft.md`，终稿为 `chXXX_final.md`

* G7落盘成功后删除临时文件

* 恢复时如发现临时文件存在，说明G3未完成

### 3.2 子Agent调用失败处理

**场景**：门禁检查中调用的工具（如指标自检（文风六卡·卡6 体检清单）、字数统计（章卡字数字段核对））执行失败。

**处理策略**：

| 失败类型         | 处理方式                                  |
| ------------ | ------------------------------------- |
| 工具不存在        | 打印警告，使用内置简化逻辑替代，记录到 `gate-log.md`     |
| 工具执行超时       | 重试1次，仍超时则跳过该项检查并标记为"待人工确认"            |
| 工具输出异常       | 记录原始输出到 `创意扰动提案（章卡元数据）`，请求人类确认 |
| 依赖缺失（如jieba） | 使用降级方案（按字符计算TTR），打印警告                 |

**原则**：工具失败不阻塞创作流程，但必须在 `gate-log.md` 中标记，并在下次会话时优先修复。

### 3.3 门禁连续失败处理

**场景**：某一门禁连续3次未通过。

**处理策略**：

1. 记录失败原因到 `门禁执行记录（章卡元数据）`
2. 暂停当前章节的写作循环
3. 向用户报告失败原因和建议修改方向
4. 等待用户指示（重写/跳过/修改大纲/调整参数）
5. 用户确认后从G1重新开始当前章节
