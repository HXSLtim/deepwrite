## 一、系统概述

本系统是一个 **自包含的小说写作循环系统**，用于从零到完稿的全流程自动化创作。系统围绕 **8级门禁控制（G0-G7 + G8人类终审）** 构建，确保每一章在写作、质检、落盘各环节均通过量化检查后才进入下一章。

### 1.1 设计目标

| 目标   | 说明                                                                                        |
| ---- | ----------------------------------------------------------------------------------------- |
| 质量达标 | σ²≥8, TTR≥0.40, Pσ²≥20, BurstCV≥0.40, ParaCV≥0.30, 3gramRep≤0.08, 3gramUniq≥0.85，消除AI检测风险 |
| 节奏合规 | 3章一小爽、10章一大爆、3:1张弛比，憋屈不超2章                                                                |
| 平台适配 | {{作品设置:目标平台}}{{作品设置:赛道}}，单章{{作品设置:单章字数下限}}-{{作品设置:单章字数上限}}字                                                                   |
| 风格稳定 | 跨章SC≥0.75，人物声音不漂移                                                                         |
| 状态持久 | 22个动态轨文件全程记录，会话断开可恢复                                                                      |

### 1.2 项目背景说明

本模板不预置任何具体项目背景。启动新书时，项目背景由阶段0（新书模式执行协议）的各步骤动态生成：

| 生成步骤          | 产出                        | 落盘位置                        |
| ------------- | ------------------------- | --------------------------- |
| 步骤1 选题市场调研    | 市场调研报告                    | 市场调研报告（素材库条目） |
| 步骤2 选题确认      | 选题确认书                     | `项目索引（作品设置·北极星）`       |
| 步骤2.5 核心创意卡录入 | 核心创意卡（AI不可改写）             | `项目索引（作品设置·北极星）`       |
| 步骤3-6         | 三幕大纲 / 人物档案 / 节奏规划 / 运营包装 | 各立项产出（素材库条目/卷/章卡）            |

> 若为已有项目的续写或重写，启动时由用户提供项目背景与已知风险（如爽点不足、节奏慢、AI检测风险、缺情感线等常见问题），作为选题与大纲阶段的规避约束，写入 `项目索引（作品设置·北极星）`。
> 新书模式完整流程见 `ORCHESTRATOR-newbook.md`。

### 1.3 门禁总览

```
G0  选题+大纲终稿人类审核（新书模式专属）
 │   ├── G1  状态加载门 — 读取22个动态轨文件
 │   ├── G2  模仿学习门 — 提取样本特征卡
 │   │   ├── G3  写作门 — 草稿生成 + 禁词扫描
 │   │   │   ├── G4  平台规则门 — 字数/节奏/合规
 │   │   │   ├── G5  metrics指标门 — σ²/TTR/Pσ²/BurstCV/ParaCV/Ngram
 │   │   │   ├── G6  动态轨一致性门 — 人物/伏笔/时间线
 │   │   │   └── G7  状态落盘门 — 15项WRITE-CHECK
 │   │   └── (循环下一章)
 │   └──
 └── G8  人类终审 — 用户阅读确认（可选，默认跳过）
```

> **铁律**：任何门禁未通过，不得进入下一阶段。门禁失败时按质检模式处理（`QC_FULL`自动重写1次，仍不通过则暂停等用户决策 / `QC_CHECK`暂停等用户决定 / `QC_SKIP`该门禁已跳过）。

### 1.4 质检模式选择（写正式篇章前必选）

> **触发时机**：阶段0全局规划完成后、第一章正式写作前，系统必须询问用户选择质检模式。
> **核心考量**：质检门禁（G4/G5/G6）及自动重写会消耗大量token，用户需根据预算自主决定。

| 模式      | 代号         | 执行门禁                     | 失败处理                     | Token消耗 | 适用场景              |
| ------- | ---------- | ------------------------ | ------------------------ | ------- | ----------------- |
| 质检+自动重写 | `QC_FULL`  | G1→G7全部门禁                | 自动重写1次，仍不通过则暂停等用户决策      | 较高      | 追求质量、想控制token消耗   |
| 仅质检不重写  | `QC_CHECK` | G1→G7全部门禁                | 暂停并报告失败项，等待用户决定是否手动修改    | 中等      | 想了解质量但不想自动消耗token |
| 跳过质检    | `QC_SKIP`  | 仅G1+G3+G7（跳过G2/G4/G5/G6） | 直接输出，用户可事后手动运行指标自检（文风六卡·卡6 体检清单） | 最低      | 预算有限、快速产出草稿       |

**执行操作**：

1. 向用户展示以上三种模式及token消耗说明
2. 等待用户选择（默认推荐`QC_FULL`）
3. 将用户选择写入 `项目索引（作品设置·北极星）` 项目信息区的"质检模式"字段
4. 后续每章循环按所选模式执行门禁

**模式切换**：用户可在任意章节切换模式（如"从下章开始只质检不重写"），更新`00_INDEX.md`即可。

**门禁执行规则**：

| 门禁                      | QC\_FULL | QC\_CHECK | QC\_SKIP |
| ----------------------- | -------- | --------- | -------- |
| G1 状态加载                 | ✅ 执行     | ✅ 执行      | ✅ 执行     |
| G2 模仿学习                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G3 写作（含R1-R5+Humanizer） | ✅ 执行     | ✅ 执行      | ✅ 执行     |
| G4 平台规则                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G5 指标门禁                 | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G6 一致性门禁                | ✅ 执行     | ✅ 执行      | ⏭️ 跳过    |
| G7 状态落盘                 | ✅ 执行     | ✅ 执行      | ✅ 执行     |

> `QC_SKIP`模式下，G3仍执行R1-R5铁律和Humanizer 单pass去AI化（内置在写作流程中，不额外消耗门禁token），但跳过G4/G5/G6的事后检查。用户可事后手动运行`指标自检（文风六卡·卡6 体检清单）`自检质量。

## 二、章节循环执行协议（G1-G7门禁）

> **触发条件**：G0通过后，或用户说"写下一章""继续写作""推进章节"时执行。
> **核心原则**：一次一章，门禁必过，状态落盘优先。

### G1：状态加载门

**目的**：加载当前章节所需的全部上下文状态。

**执行操作**：**上下文由 DeepWrite 原生注入**（章卡/人物卡/连续性/伏笔/时间线/世界观/作品设置随会话自动带入，无需手动加载）；下表为原生结构对照，按需读取字段即可：

**G1通过条件**：

* 原生上下文齐备：章卡、人物卡、连续性摘要等已在会话上下文中，字段可按需读取

* `progress.md` 中的当前章号与即将写作的章号一致

* `character-state.md` 中各角色状态与上一章结尾一致（含年龄/外貌状态/知识状态）

* `foreshadowing.md` 中无超期未回收的红色伏笔（按scope预警阈值检查，如有则标记并在本章处理）

* `timeline.md` 中时间线连续，无时间倒流矛盾（闪回除外）

* `main-quest.md` 中主线未停滞（连续3章无推进则标记预警）

* `location-index.md` 中本章场景地点已登记（新地点需录入）

* `continuity-brief.md` 已含上一章尾幕快照（尾幕时刻/地点/在场POV/情绪基调/最后一句钩子全文引用），缺失则回读上一章原文生成

* `current-state.md` 中此刻时刻/地点与 `timeline.md`+`location-index.md` 交叉一致，无冲突

**G1失败处理**：

* 文件读取失败 → 创建空文件并记录警告

* 状态不一致 → 以最近一次G7落盘的状态为准，覆盖不一致项

### G2：模仿学习门

**目的**：从同类爆款中提取写作特征卡，为本章写作提供风格参照。

**执行操作**：

1. **加载反AI模式清单**：读取 `anti-ai-patterns.md`，提取4层检测规则（词汇/句式/结构/情节），作为本章写作的风格约束注入G3

0.5. **加载切片样本库**：扫描 `slices/` 目录，按本章需求匹配切片：

* 按题材加载：读取 `slices/by_genre/[题材]/` 下的切片文件

* 按技巧加载：根据本章场景类型（打脸/情感/战斗/日常），读取 `slices/by_technique/[技巧]/` 下对应切片

* 按场景加载：根据本章位置（章首/章尾/对话/内心），读取 `slices/by_scene/[场景]/` 下对应切片

* 用 `指标自检（文风六卡·卡6 体检清单）` 计算各切片的 σ²/TTR/Pσ²/BurstCV/ParaCV 参考值

* 若切片库为空（用户未添加），跳过本步，使用步骤1的网络刷新样本

1. **样本刷新**（仅首次 + 风格漂移时刷新，不再每10章固定刷新）：

   * 用 WebSearch 搜索同类爆款章节片段

   * 搜索关键词模板：`[题材类型] 爆款片段 [章节类型] 示例`

   * 抓取2-3个高热度片段作为新样本

   * 用 `指标自检（文风六卡·卡6 体检清单）` 计算样本的 σ²/TTR/Pσ²/BurstCV/ParaCV/Ngram 参考值

   * 将样本特征卡存入 `素材库样本条目`

2. **样本特征卡提取**：

   * 入场方式（dialogue/scene/action/sensory/psychological/narrative）

   * 章末钩子类型（悬念/反转/预告/情感/信息差）

   * 对话占比参考值

   * σ²/TTR/Pσ²/BurstCV/ParaCV/Ngram 参考值

   * 节奏特征（快节奏/中速/慢热）

3. **本章匹配**：

   * 根据本章在大纲中的类型（爽点章/过渡章/情感章/爆点章），匹配最合适的样本

   * 提取本章写作目标特征卡

**G2通过条件**：

* `sample-library.md` 中至少有1个与本章类型匹配的样本

* 样本特征卡提取完成（入场方式+钩子类型+6项metrics参考值）

**G2失败处理**：

* 样本库为空 → 用默认特征卡（σ²≥10, TTR≥0.48, BurstCV≥0.50, Pσ²≥28, ParaCV≥0.40, 3gramUniq≥0.90）

* 样本不匹配 → 使用最近一次刷新的通用样本

### G3：写作门

**目的**：生成本章草稿并进行禁词扫描。

**执行操作**：

1. **写作前准备**：

   * 加载本章大纲条目（内容摘要+情绪落点+章末钩子）

   * 加载本章涉及角色的Soul Field和**角色语言档案**（来自步骤4，含词汇偏好/句式/口头禅/情绪表达/禁用词）

   * 加载G2提取的样本特征卡

   * 加载主角语言指纹库

   * 检查 `rhythm_tracker.json` 确认本章是否为爽点章/爆点章

   * **加载写作Agent prompt**：读取 `writer-prompt.md`，作为草稿生成的系统prompt，注入以下约束：

     * 写作优先级：冲突 > 好奇心 > 情感 > 进度 > 描写

     * 场景公式：每个场景必须包含目标/冲突/风险/神秘/决策

     * 章节公式：开头→冲突→升级→决策→钩子

     * 冲突引擎：生成多层冲突（外部/内部/社会/资源/时间压力/身份）

     * 好奇心引擎：制造问题但不立刻回答

     * 留存检查清单：冲突/好奇心/进度/情感张力/钩子/结尾期待

   * **加载题材适配参数**：读取 `genre-guides.md`，提取当前题材的：

     * 对话占比目标（如古言50-70%/都市40-60%/玄幻30-50%）

     * 爽点密度（如3章1爽/5章1爽）

     * 铺垫容忍度

     * 按场景类型动态调整对话占比（冲突60-80%/日常40-60%/过渡20-40%）

   * **加载钩子系统**：读取 `suspense-hooks.md`，选择本章钩子类型（10种），设计章末钩子

   * **加载文风六卡（L3 常驻）**：读取 `文风六卡.md`，随 writer-prompt 一起常驻注入——每句四关（语气/语序/AI味/标点）优先级高于文采，写/改每一句必过

2. **Scene-Sequel场景规划**（草稿生成前必做）：

   * 从 `scene-plan.md` 加载场景规划模板

   * 为本章每个场景填写Scene-Sequel结构：

     * **Scene层**：Goal（场景目标）→ Conflict（3层递进阻碍）→ Disaster（灾难结尾，禁止"干净成功"）

     * **Sequel层**：Reaction（即时身心反应，实时呈现）→ Dilemma（两难选项，各有代价）→ Decision（决策生成下一场景Goal）

   * 灾难类型必须选其一：flat\_no（直接失败）/ yes\_but（达成但带来新问题）/ no\_and\_furthermore（失败且更糟）

   * 标注爽点模式（越级反杀/打脸权威/反派翻车/甜蜜超预期/无）

   * 将填写完成的场景规划存入 `章卡规划区`（从模板复制到动态轨）

   * **检查清单**：每个场景有Goal、Conflict≥3层、以Disaster结尾、无"yes"场景、Sequel中Reaction实时呈现

3. **技法卡路由（L2 弹药 · 章型判定 + 取卡 + 亮凭证）**：

## 三、执行原则

### 3.1 核心原则

| 原则         | 说明                                             |
| ---------- | ---------------------------------------------- |
| **一次一章**   | 每次循环只写一章，不批量生成。每章完成后等待用户指示或自动进入下一章             |
| **门禁必过**   | 任何门禁未通过不得进入下一阶段。QC\_FULL模式下自动修复1次，仍不通过则暂停等用户决策 |
| **用户只审G8** | G1-G7全自动执行，用户只需在G8（人类终审）时介入。前3章除外——前3章强制G8审核   |
| **状态落盘优先** | 任何操作完成后立即落盘。宁可多写一次文件，不可丢失状态                    |

### 3.2 写作约束优先级

当约束冲突时，按以下优先级处理：

```
1. 平台合规（违禁词/意识形态）— 一票否决
2. Soul Field一致性 — 不可违背
3. 核心创意卡约束 — 不可偏离
4. 节奏铁律（3章爽/10章爆/憋屈≤2） — 必须满足
5. metrics指标门限 — 必须达标
6. 字数标准（{{作品设置:单章字数下限}}-{{作品设置:单章字数上限}}） — 参考指标，不阻塞
7. 伏笔回收时效 — 超期强制处理
8. 文风稳定性 — 尽量保持
```

### 3.3 自动化与人工分工

| 环节          | 自动/人工     | 说明             |
| ----------- | --------- | -------------- |
| 选题市场调研      | 自动执行，人工确认 | AI搜索+整理，用户确认方向 |
| 核心创意卡       | 人工填写      | 作者提供5项核心设定     |
| 大纲/人物/节奏    | 自动执行，人工确认 | AI生成，用户审核      |
| 章节写作（G1-G7） | 全自动       | 门禁自动执行         |
| 前3章审核       | 强制人工      | 前三章必须G8审核      |
| 后续章节审核      | 可选人工      | 默认跳过G8，用户可随时介入 |
